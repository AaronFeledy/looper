# task 10 — stall proof: permission gate hold vs control

## What was proven
A: run blocked on a pending human permission gate scores no stall strikes.
B (control): the equivalent quiescent no-progress run with the gate answered does accumulate strikes and trips.

A already holds in production via probeInFlight; no prod change was needed.
Chain proven by the test (real code, only the opencode client is faked):
  session.status busy -> probeBackgroundLiveness -> createInFlightProbe -> StallObservation.inFlight -> detector HOLDs the counter
Second (primary) mechanism, documented in the test comment, not re-tested here: while the gate is open the step timeout is paused and runIteration has not returned, so runStallCheck is never reached.
