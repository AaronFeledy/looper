task 9 - TUI wire modal + keys + bell + help/footer
====================================================

Implementation
- src/tui/permission-dialog.ts (new) - createPermissionDialog: floating gate modal,
  zIndex 300 (above help/prompt/config), visible only while modalFocusWinner(state) === "permission".
- src/tui/permission-gate.ts - gateModalContent(requests) + queueSummaryLine(count): head details,
  lastError (D-error reclaim), decision keys, queue depth. Pure, no renderer/client imports.
- src/tui/keys.ts - gate key block placed after the esc branch and before the escConfirm dismissal so
  modalFocusWinner precedence (recovery > escConfirm > permission) is the single source of truth.
  y/a/d/s -> tryClaimPendingRequestDecision({requestID, generation, action}) against the queue head
  (permission) / d,s (question). q passes through to quit; ctrl-c interrupt handled earlier; every
  other key is swallowed by the gate. The TUI never calls onSkip - the broker fires skip only after
  its reject lands (src/opencode/request-broker.ts:108).
- src/config/tunables.ts - permissionBellEnabled(): LOOPER_PERMISSION_BELL, default ON,
  "0"/"false"/"off"/"no" opt out.
- src/tui/permission-bell.ts (new) - createPermissionBell(state, {enabled, isTTY, write}); one BEL
  (\u0007) per batch of newly gated requests, never when disabled or off-TTY, forgets resolved ids so a
  re-ask alerts again, returns a detach fn.
- src/tui/help-overlay.ts - "y/a/d/s answer permission ask" + "d/s reject/skip a question";
  dialog maxHeight 18 -> 20 so all 17 bindings still render at 40x24.
- src/tui/footer.ts - gate hint after the recovery branch: "agent is waiting on you - [y] once
  [a] always  [d] deny  [s] deny + skip  (+N waiting)  [q]uit" (question head shows [d]/[s]).
- src/tui/pending-request-panel.ts - per-request in-looper keys + queue-depth summary line.
- src/main.ts - dialog composed above the pending-request panel; bell created next to bindKeys and
  detached on both the normal finally and the force-kill path.
